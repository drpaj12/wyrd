# W2 Wyrd III GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PySide6 desktop GUI (`wyrd-gui`) over W1 projects: project tree, source viewer, `wyrd.toml` editor with live validation, flow runner, Quartus-style report, Messages pane with click-through, VPR floorplan launcher, settings dialog, About with citations.

**Architecture:** All logic that can be Qt-free lives in `wyrd/guimodel/` and `wyrd/citations.py` and is tested with `unittest`. Thin Qt widgets in `wyrd/gui/` only display those models and start `wyrd run` as a `QProcess`. Four small backward-compatible hooks are added to W1 (spec Section 9). Core `wyrd` stays standard-library-only.

**Tech Stack:** Python 3.11+, PySide6-Essentials 6.x (QtCore, QtGui, QtWidgets), `unittest`, ruff, `mypy --strict`.

**Spec:** `docs/specs/2026-10-21-w2-gui-design.md` (read it first; Section numbers below refer to it). W1: `docs/specs/2026-10-21-w1-runner-design.md`.

## Global Constraints

- Work in a worktree on a branch, never on `main`; PR with green CI, squash merge (repo `CLAUDE.md`).
- Python 3.11+, no 3.12-only syntax. Runtime dependencies of core: none. `[project] dependencies = []` stays.
- Nothing outside `wyrd/gui/` imports `PySide6`. `wyrd/gui/` modules import `wyrd.guimodel`, `wyrd.report`, `wyrd.project`, `wyrd.settings`, `wyrd.store`, never `odin3`.
- `ruff check .` and `mypy --strict wyrd tests` clean (needs `pip install -e ".[gui]"`). No `# noqa`, `# type: ignore` or other suppressions without Peter's approval; if PySide6 typing blocks strict mypy, stop and ask.
- Small functions. Tests are `unittest` under `tests/`; GUI tests use `@unittest.skipUnless(importlib.util.find_spec("PySide6"), ...)`.
- Exit codes of `wyrd` unchanged (0 all ok, 1 some not ok, 2 usage/config/preflight).
- PySide6 names to use are exactly those in the task text; all exist in 6.12.0. Notes: the extra-selection type is `QTextEdit.ExtraSelection` (not on `QPlainTextEdit`); `QSettings.Format.IniFormat`, `QProcess.ProcessChannelMode.SeparateChannels`, `Qt.ItemDataRole.UserRole`, `Qt.DockWidgetArea.BottomDockWidgetArea` are the enum spellings.
- Commit and push after every task (`git push -u origin <branch>` first time). No emojis, no em-dashes in code, comments or docs.
- Setup once: `python3 -m venv .venv && .venv/bin/pip install -e ".[gui]" ruff mypy` (after Task 2; before it, `pip install -e . ruff mypy`). Test command: `.venv/bin/python -m unittest discover -s tests -t . -v`; single module: `.venv/bin/python -m unittest tests.test_x -v`.

## Review Focus

Failure modes the spec implies that no single task's main tests would catch. Each has a test in the task named.

1. A project whose `wyrd.toml` is broken on open: the window must open, show the error with its line, and keep the editor usable (Task 8, 12).
2. A log line that looks like a location but is not (a `--vtr:` prefix, `10:30` in a message): must not produce a wrong `file:line` (Task 4).
3. A run directory with no `wyrd.db`, an empty db, a run whose metrics are missing (`crit_path_ns` absent or 0): Summary shows `n/a`, never a crash or a division by zero (Task 5, 10).
4. A huge or binary file opened in the viewer or as a log: refused or replaced, never frozen UI (Task 9).
5. Quitting or switching project while a flow is running or the editor has unsaved text: confirm, never silently lose or orphan (Task 11, 12).
