# W3 Simulation (`wyrd.bifrost` and the GUI sim panel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A session layer `wyrd.bifrost` over Odin III's per-cycle simulator (named inputs and outputs, step, reset, recording, VCD, vector files, a `wyrd sim` command) and a Simulate tab in the W2 GUI (vector editor, random run, built-in waveform view, Open in GTKWave); both W4 and the panel are clients.

**Architecture:** `wyrd/bifrost/` is Qt-free and pygame-free and talks to a `Backend` protocol; `Odin3Backend` is the only code that imports `odin3` (lazily, inside a function). Tests use a Python fake of the S1 `traffic.v` fixture, so CI needs no Odin III. Waveform and value logic is Qt-free in `wyrd/guimodel/waveform.py`; the Qt widgets in `wyrd/gui/` only draw it.

**Tech Stack:** Python 3.11+, standard library at runtime; optional extra `sim = ["odin3>=1.2"]`; PySide6-Essentials (W2) for the panel; `unittest`, ruff, `mypy --strict`.

**Spec:** `docs/specs/2026-10-21-w3-sim-design.md` (read it first; section numbers below refer to it). Also read the S1 spec `docs/specs/2026-10-21-s1-sim-api-design.md` and plan in the Odin III repository (`/home/jamiespa/odin3-ws/work/odin3-s1/docs/`), and W1 (`docs/specs/2026-10-21-w1-runner-design.md`) and W2 (`docs/specs/2026-10-21-w2-gui-design.md`).

## Global Constraints

- Work in a worktree on a branch, never on `main`; PR with green CI, squash merge (repo `CLAUDE.md`).
- Python 3.11+, no 3.12-only syntax. `[project] dependencies = []` stays; the new extra is `sim = ["odin3>=1.2"]`.
- `import odin3` only in `wyrd/bifrost/backend.py`, inside a function. Nothing outside `wyrd/gui/` imports `PySide6`. `wyrd/bifrost/` and `wyrd/guimodel/` import neither.

- Tests are `unittest` under `tests/`; GUI tests use `@unittest.skipUnless(importlib.util.find_spec("PySide6"), ...)` and `QT_QPA_PLATFORM=offscreen`; real-Odin tests skip unless `odin3_available()`.
- Small functions. No emojis, no em-dashes in code, comments or docs. Commit and push after every task.
- Exact spec values: S1 log levels 0 error, 1 warning, 2 info; compile script `read_verilog "A" "B"; proc; opt; lower`; one cycle is 10 VCD time units, timescale `1ns`; VCD codes base 94 from `!`; vector line `CYCLE INPUTS [OUTPUTS]`, ports MSB first.
- Order: Tasks 1 to 8 need only W1 code (this repo at `main`). Tasks 9 to 11 need W2 merged (`wyrd/gui/mainwindow.py`, `wyrd/guimodel/`, `tests/test_gui_smoke.py`). Start W4 only after Task 8.

## Review Focus

1. `set` on a clock, an output, an internal or an unknown name, or with a negative, too-wide or 64-bit-plus value: a clear error, nothing changed (Tasks 4, 6).
2. Use after close, double close, a compile that fails halfway: no leaked handle, `SessionClosed` for later calls (Task 4).
3. Vector files from Windows editors and by hand: CRLF, blank lines, comment lines, a header that does not match, wrong width, skipped cycle numbers, a design with no data input (Task 6).
4. A design with no clock and no output, and `step(0)`: no crash, empty rows (Tasks 4, 5).
5. A compile error in the second of two files; a path with a space; a warning-only compile: the diagnostic names the right file and line, the warnings are kept (Tasks 2, 3).
