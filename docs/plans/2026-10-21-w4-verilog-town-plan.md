# W4 Midgard III (Verilog Town) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the game verilogTown to Python and pygame-ce as Midgard III (command `midgard`, extra `wyrd[midgard]`): all 13 levels (0 to 12), cars, lights, sensors, scoring, high scores, level select, the original's Verilog editor window and level editor (PySide6), with each traffic light driven by the player's Verilog through Bifrost III (`wyrd.bifrost`, W3), one Bifrost III step per game tick (1 game tick = 1 rising clock edge of the player's module; fixed-step deterministic game time, spec 5.9). Governing principle (spec 2): where a choice differs from the original verilogTown, the original wins; the stated deviations are listed in spec 13.

**Architecture:** `wyrd/midgard/model/` ports the Java mechanics method by method and imports neither pygame nor Qt nor odin3; `wyrd/midgard/ui/` draws and handles input with pygame-ce; a `LightController` seam connects the engine to Bifrost III (or to Python scripted controllers in tests). Assets (original images and level files, MIT) are copied into `wyrd/midgard/assets` by a committed tool.

**Tech Stack:** Python 3.11+, pygame-ce 2.5.x (verified names, Section "pygame-ce names" below), Bifrost III (W3), `unittest`, ruff, `mypy --strict`.

**Spec:** `docs/specs/2026-10-21-w4-verilog-town-design.md` (read it first; section numbers below refer to it; its Section 5 pseudocode is normative). Also read W3 (`docs/specs/2026-10-21-w3-sim-design.md`, `docs/plans/2026-10-21-w3-sim-plan.md`). ## Review Focus

1. A player file that does not compile, lacks a port, has a wrong-width port, or was deleted: the level stays in EDIT, the error shows with `file:line`, nothing crashes (Tasks 8, 10).
2. A car whose destination is unreachable, and a map where no end tile is reachable: forced and counted once, never an exception (Task 3, 5).
3. Missing or garbled user files: `sensorFile.txt` with junk lines or a sensor on a bad tile, `high_score.txt` empty or garbled, no data directory yet (Task 7).
4. Verilog output codes 5 to 7, and a `SimError` while a level runs: STOP with a warning line, pause with a message (Tasks 5, 8, 10).
5. Mouse and window: clicks in the letterbox bars, clicks outside the visible tiles, a tiny window, an editor that saves by atomic rename or a file deleted while the game runs (Tasks 7, 9, 10).
