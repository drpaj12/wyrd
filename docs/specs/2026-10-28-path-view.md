# Path view (Paths panel)

Date 2026-10-28. Branch `feat/path-view`. Purpose: hub RQ W Q3.3; measure: speed = critical plus
near-critical paths. Reads Mímir schema 6 (`timing_path`, `timing_path_node`; Mímir
`docs/specs/2026-10-28-timing-paths.md`).

## Model

`mimirview.MimirView.paths_through(run_id, span, word, bit, module, min_crit)` lists the stored paths
(most critical first); `path_detail(run_id, index)` gives one path's nodes in order (named
`path_detail` because `MimirView.path` is the store file). A store without the tables, or a run
without path rows, returns no paths and the note "this store has no per-path data; run mimir
import-timing --paths-from-blobs".

## Panel and source view

Click a hot word or line in the source view (Show HDL heat). The Paths panel lists the paths through
it: rank, crit, slack, start -> end, nodes. The click asks, in order, for the bit of the word on that
line, the word on that line, the line; the first that finds paths is shown. Choosing a path draws it
in the source view: numbered step markers with the step delay in a gutter column, every line off the
path dimmed (the heat colours stay). The step table lists file:line, word[bit], module, delay;
clicking a step scrolls to it, and a step in another file opens that file (found as the heat view
finds files). Previous/Next walk the list. "All paths through here" tints the lines of the paths with
crit >= max(0.90, cut-off) by the largest crit among them.

## Near-critical cut-off

One setting in the panel (0.90 default, 0.95, 0.99, off), stored in QSettings (`pathsCutoff`), stated
in the panel header. A path below it is not listed, drawn or marked; the data stays in the store. The
base hot/cold colouring keeps its own scope control in the Timing panel.
